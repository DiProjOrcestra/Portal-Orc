Casos de Uso — Ciclo 2

Especificação dos casos de uso referentes ao Ciclo 2 de desenvolvimento, contemplando os requisitos funcionais RF08, RF09, RF10, RF11 e RF12 (Perfil do Membro) e RF35, RF36, RF37 e RF38 (Segurança de Acesso). O identificador e o nome de cada caso de uso correspondem diretamente ao requisito funcional de origem, e as regras de negócio (RN) aplicáveis estão indicadas nas etapas correspondentes de cada fluxo, na mesma convenção adotada nos casos de uso do Ciclo 1. Referências a UC-05, UC-19, UC-21 e UC-33 apontam para os casos de uso já especificados na página do Ciclo 1.

UC-08: Consultar dados pessoais do perfil

Objetivo: Exibir no perfil do membro suas informações pessoais e sociais — sobre mim, gostos, história na Orc'estra e foto de perfil — além do tempo de casa (dias de Orc'estra), permitindo que os demais membros conheçam melhor o colega.

Atores: Usuário (todos os perfis)

Pré-condições

  • Usuário está autenticado na plataforma. (UC-33)
  • Perfil do membro consultado está previamente cadastrado. (UC-05)

Fluxo Principal

  1. Usuário acessa a página de perfil de um membro (o próprio perfil ou o de outro colaborador).
  2. Sistema verifica a autenticação do usuário. (UC-33)
  3. Sistema busca as informações pessoais cadastradas do membro: sobre mim, gostos, história na Orc'estra e foto de perfil. (FA-A1)(FE-E1)
  4. Sistema calcula os dias de Orc'estra do membro com base na data de entrada registrada no cadastro. (UC-05)
  5. Sistema exibe as informações pessoais e os dias de Orc'estra na aba "Sobre mim" do perfil. (FA-A2)

Fluxos Alternativos

FA-A1 — Campo pessoal não preenchido

  1. Sistema identifica que um ou mais campos pessoais (sobre mim, gostos ou foto de perfil) não foram preenchidos pelo membro.
  2. Sistema exibe um espaço reservado indicando que a informação ainda não foi preenchida.
  3. Fluxo retorna ao passo 5 do Fluxo Principal.

FA-A2 — Visualização do próprio perfil

  1. Sistema identifica que o membro consultado é o próprio usuário autenticado.
  2. Sistema disponibiliza o atalho de edição das informações pessoais. (UC-12)
  3. Fluxo retorna ao passo 5 do Fluxo Principal.

Fluxos de Exceção

FE-E1 — Perfil do membro não encontrado

  1. Sistema não localiza o perfil do membro selecionado.
  2. Sistema interrompe a consulta.
  3. Sistema informa que o perfil não foi encontrado.

Pós-condições

Sucesso

  • Informações pessoais e dias de Orc'estra do membro exibidos ao usuário.

Falha

  • Nenhuma informação pessoal exibida.

Casos de Uso Relacionados

  • UC-05
  • UC-09
  • UC-12
  • UC-33

UC-09: Consultar dados profissionais do perfil

Objetivo: Exibir no perfil do membro suas informações profissionais — competências técnicas, Plano de Desenvolvimento Individual (PDI) e áreas de interesse — apoiando a identificação de talentos e a alocação de equipes.

Atores: Usuário (todos os perfis)

Pré-condições

  • Usuário está autenticado na plataforma. (UC-33)
  • Perfil do membro consultado está previamente cadastrado. (UC-05)

Fluxo Principal

  1. Usuário acessa a aba de dados profissionais do perfil de um membro.
  2. Sistema verifica a autenticação do usuário. (UC-33)
  3. Sistema busca as competências técnicas, o PDI e as áreas de interesse cadastradas do membro. (FA-A1)(FE-E1)
  4. Sistema exibe as competências técnicas, o PDI e as áreas de interesse do membro. (FA-A2)

Fluxos Alternativos

FA-A1 — Dados profissionais não preenchidos

  1. Sistema identifica que o membro ainda não preencheu competências técnicas, PDI ou áreas de interesse.
  2. Sistema exibe mensagem informando que a informação ainda não foi cadastrada.
  3. Fluxo retorna ao passo 4 do Fluxo Principal.

FA-A2 — Visualização do próprio perfil

  1. Sistema identifica que o membro consultado é o próprio usuário autenticado.
  2. Sistema disponibiliza o atalho de edição das informações profissionais. (UC-12)
  3. Fluxo retorna ao passo 4 do Fluxo Principal.

Fluxos de Exceção

FE-E1 — Perfil do membro não encontrado

  1. Sistema não localiza o perfil do membro selecionado.
  2. Sistema interrompe a consulta.
  3. Sistema informa que o perfil não foi encontrado.

Pós-condições

Sucesso

  • Competências técnicas, PDI e áreas de interesse do membro exibidos ao usuário.

Falha

  • Nenhuma informação profissional exibida.

Casos de Uso Relacionados

  • UC-05
  • UC-08
  • UC-12
  • UC-33

UC-10: Consultar status de alocação do membro

Objetivo: Exibir no perfil do membro seu histórico de alocação em projetos e o status situacional atual (alocado, disponível, em férias ou afastado), apoiando o mapeamento técnico da empresa.

Atores: Usuário (todos os perfis)

Pré-condições

  • Usuário está autenticado na plataforma. (UC-33)
  • Perfil do membro consultado está previamente cadastrado. (UC-05)

Fluxo Principal

  1. Usuário acessa a aba de alocação do perfil de um membro.
  2. Sistema verifica a autenticação do usuário. (UC-33)
  3. Sistema busca o histórico de alocação em projetos e o status situacional vigente do membro. (FA-A1)(FE-E1)
  4. Sistema exibe o histórico de alocação e o status situacional atual do membro (alocado, disponível, em férias ou afastado). (RN07)
  5. Sistema disponibiliza o atalho de atualização do status apenas aos usuários do núcleo TOPS ou da Direx. (RN06) (FA-A2)

Fluxos Alternativos

FA-A1 — Nenhum histórico de alocação registrado

  1. Sistema identifica que o membro ainda não possui histórico de alocação em projetos.
  2. Sistema exibe apenas o status situacional atual do membro.
  3. Fluxo retorna ao passo 5 do Fluxo Principal.

FA-A2 — Acesso de usuário autorizado à atualização do status

  1. Sistema identifica que o usuário pertence ao núcleo TOPS ou à Direx. (RN06)
  2. Sistema disponibiliza o atalho para a atualização do status situacional do membro.
  3. Fluxo retorna ao passo 5 do Fluxo Principal.

Fluxos de Exceção

FE-E1 — Perfil do membro não encontrado

  1. Sistema não localiza o perfil do membro selecionado.
  2. Sistema interrompe a consulta.
  3. Sistema informa que o perfil não foi encontrado.

Pós-condições

Sucesso

  • Histórico de alocação e status situacional do membro exibidos ao usuário.

Falha

  • Nenhuma informação de alocação exibida.

Casos de Uso Relacionados

  • UC-05
  • UC-33

UC-11: Consultar planos de ação estratégicos vinculados ao membro

Objetivo: Exibir no perfil do membro os planos de ação e objetivos estratégicos do ano aos quais ele está vinculado, permitindo visualizar seu envolvimento na execução da estratégia da empresa.

Atores: Usuário (todos os perfis)

Pré-condições

  • Usuário está autenticado na plataforma. (UC-33)
  • Perfil do membro consultado está previamente cadastrado. (UC-05)
  • Membro foi vinculado a pelo menos um plano de ação para que haja conteúdo a exibir. (UC-19)

Fluxo Principal

  1. Usuário acessa a aba de planos de ação do perfil de um membro.
  2. Sistema verifica a autenticação do usuário. (UC-33)
  3. Sistema busca os planos de ação e os objetivos estratégicos do ano aos quais o membro está vinculado. (UC-19) (FA-A1)(FE-E1)
  4. Sistema exibe a lista de planos de ação e objetivos estratégicos vinculados ao membro, com o status atual de cada um. (UC-21)

Fluxos Alternativos

FA-A1 — Membro sem vínculo a planos de ação

  1. Sistema identifica que o membro não está vinculado a nenhum plano de ação.
  2. Sistema exibe mensagem informando que o membro não possui planos de ação vinculados no momento.
  3. Fluxo retorna ao passo 4 do Fluxo Principal.

Fluxos de Exceção

FE-E1 — Perfil do membro não encontrado

  1. Sistema não localiza o perfil do membro selecionado.
  2. Sistema interrompe a consulta.
  3. Sistema informa que o perfil não foi encontrado.

Pós-condições

Sucesso

  • Planos de ação e objetivos estratégicos vinculados ao membro exibidos ao usuário.

Falha

  • Nenhum plano de ação exibido.

Casos de Uso Relacionados

  • UC-05
  • UC-19
  • UC-21
  • UC-33

UC-12: Editar perfil do membro

Objetivo: Permitir que o membro edite as informações pessoais e profissionais do próprio perfil, mantendo seus dados atualizados na plataforma.

Atores: Usuário (todos os perfis)

Pré-condições

  • Usuário está autenticado na plataforma. (UC-33)
  • Usuário possui perfil previamente cadastrado. (UC-05)

Fluxo Principal

  1. Usuário acessa a opção de edição do próprio perfil.
  2. Sistema exibe o formulário de edição com as informações pessoais (sobre mim, gostos, história na Orc'estra, foto de perfil) e profissionais (competências técnicas, PDI, áreas de interesse) atualmente cadastradas. (UC-08) (UC-09)
  3. Usuário edita as informações desejadas.
  4. Sistema valida os dados informados, verificando formato e preenchimento dos campos obrigatórios. (FE-E1)
  5. Sistema processa e salva as alterações realizadas.
  6. Sistema registra a operação no log de auditoria, contendo usuário, ação, data/hora e módulo afetado.
  7. Sistema confirma a atualização do perfil. (UC-08) (UC-09)

Fluxos Alternativos

Não se aplicam fluxos alternativos a este caso de uso.

Fluxos de Exceção

FE-E1 — Dados inválidos na edição

  1. Sistema identifica campos obrigatórios não preenchidos ou conteúdo em formato inválido.
  2. Sistema interrompe o salvamento das alterações.
  3. Sistema informa o usuário sobre os campos que precisam de correção.

Pós-condições

Sucesso

  • Perfil do membro atualizado.
  • Alteração registrada no log de auditoria.

Falha

  • Nenhuma alteração salva.
  • Perfil do membro permanece inalterado.

Casos de Uso Relacionados

  • UC-05
  • UC-08
  • UC-09
  • UC-33

UC-35: Expirar sessão por inatividade

Objetivo: Encerrar automaticamente a sessão do usuário após um período definido de inatividade, exigindo nova autenticação para reforçar a segurança do acesso à plataforma.

Atores: Sistema (acionado automaticamente por inatividade), Usuário (todos os perfis)

Pré-condições

  • Usuário está autenticado na plataforma. (UC-33)

Fluxo Principal

  1. Sistema monitora o tempo de inatividade do usuário durante a sessão.
  2. Sistema identifica que o tempo de inatividade atingiu o limite definido. (FA-A1)
  3. Sistema encerra automaticamente a sessão do usuário.
  4. Sistema registra o encerramento da sessão por inatividade, incluindo usuário e data/hora.
  5. Sistema redireciona o usuário para a tela de login, exigindo nova autenticação. (UC-33)
  6. Sistema informa ao usuário que a sessão foi encerrada por inatividade.

Fluxos Alternativos

FA-A1 — Usuário retoma atividade antes do limite

  1. Sistema identifica uma nova interação do usuário antes de atingir o tempo limite de inatividade.
  2. Sistema reinicia a contagem do tempo de inatividade.
  3. Fluxo retorna ao passo 1 do Fluxo Principal.

Fluxos de Exceção

FE-E1 — Erro ao processar a expiração da sessão

  1. Sistema tenta encerrar a sessão do usuário por inatividade.
  2. Sistema identifica falha técnica ao processar o encerramento (ex.: indisponibilidade do serviço de sessões).
  3. Sistema mantém a sessão ativa e registra a falha para análise técnica posterior.

Pós-condições

Sucesso

  • Sessão do usuário encerrada.
  • Novo login exigido para acesso às funcionalidades da plataforma.

Falha

  • Sessão permanece ativa além do tempo de inatividade definido.

Casos de Uso Relacionados

  • UC-33

UC-36: Bloquear conta por tentativas de login malsucedidas

Objetivo: Bloquear temporariamente o acesso do usuário após um número determinado de tentativas de login consecutivas malsucedidas, notificando-o por e-mail, para proteger a conta contra tentativas indevidas de acesso.

Atores: Sistema (acionado automaticamente durante o login), Usuário (todos os perfis)

Pré-condições

  • Usuário possui conta cadastrada na plataforma. (UC-05)
  • Usuário está na tela de login. (UC-33)

Fluxo Principal

  1. Usuário informa e-mail e senha na tela de login. (UC-33)
  2. Sistema valida as credenciais informadas e identifica que a senha está incorreta.
  3. Sistema registra a tentativa de login malsucedida, associada à conta do usuário.
  4. Sistema verifica se o número de tentativas consecutivas malsucedidas atingiu o limite definido. (FA-A1)
  5. Sistema bloqueia temporariamente o acesso à conta do usuário.
  6. Sistema envia uma notificação por e-mail ao usuário informando o bloqueio e as opções disponíveis: redefinição de senha ou aguardo do prazo de bloqueio. (FE-E1)
  7. Sistema registra o bloqueio no log de auditoria, contendo usuário, ação e data/hora.
  8. Sistema informa ao usuário, na tela de login, que a conta foi temporariamente bloqueada.

Fluxos Alternativos

FA-A1 — Limite de tentativas ainda não atingido

  1. Sistema identifica que o número de tentativas consecutivas malsucedidas ainda não atingiu o limite definido.
  2. Sistema informa ao usuário que as credenciais são inválidas e solicita nova tentativa.
  3. Fluxo retorna ao passo 1 do Fluxo Principal.

Fluxos de Exceção

FE-E1 — Falha no envio da notificação por e-mail

  1. Sistema tenta enviar a notificação de bloqueio por e-mail.
  2. Sistema identifica falha no envio (e-mail inválido ou serviço de envio indisponível).
  3. Sistema interrompe o envio.
  4. Sistema mantém o bloqueio da conta e registra a falha de notificação no log de auditoria.

Pós-condições

Sucesso

  • Conta do usuário bloqueada temporariamente.
  • Notificação de bloqueio enviada ao e-mail cadastrado.

Falha

  • Conta permanece acessível.
  • Nenhum bloqueio aplicado.

Casos de Uso Relacionados

  • UC-33
  • UC-37

UC-37: Redefinir senha via e-mail

Objetivo: Permitir que o usuário solicite a redefinição da própria senha a partir do e-mail cadastrado, definindo uma nova senha que atenda aos critérios mínimos de segurança, sem a necessidade de contato com o núcleo TOPS/Direx.

Atores: Usuário (todos os perfis, autenticado ou não)

Pré-condições

  • Usuário possui conta e e-mail cadastrados na plataforma. (UC-05)

Fluxo Principal

  1. Usuário seleciona a opção "Esqueci minha senha" na tela de login.
  2. Usuário informa o e-mail cadastrado.
  3. Sistema verifica se o e-mail informado corresponde a uma conta cadastrada. (FE-E1)
  4. Sistema gera um link/token de redefinição de senha com validade limitada.
  5. Sistema envia o link/token para o e-mail cadastrado do usuário. (FE-E2)
  6. Usuário acessa o link recebido e informa a nova senha e a confirmação da nova senha.
  7. Sistema valida o token quanto à validade e verifica se a nova senha atende aos critérios mínimos de segurança e a correspondência entre os campos. (RN17) (FE-E3)(FE-E4)
  8. Sistema processa a atualização, substituindo a senha anterior pela nova senha definida.
  9. Sistema invalida o link/token de redefinição utilizado.
  10. Sistema registra a operação no log de auditoria, contendo usuário, ação e data/hora.
  11. Sistema confirma a redefinição de senha e redireciona o usuário para a tela de login. (UC-33)

Fluxos Alternativos

Não se aplicam fluxos alternativos a este caso de uso.

Fluxos de Exceção

FE-E1 — E-mail não cadastrado

  1. Sistema identifica que o e-mail informado não corresponde a nenhuma conta cadastrada.
  2. Sistema interrompe a solicitação.
  3. Sistema exibe mensagem genérica informando que, caso o e-mail esteja cadastrado, um link de redefinição será enviado, sem confirmar a existência da conta.

FE-E2 — Falha no envio do e-mail

  1. Sistema tenta enviar o link/token de redefinição de senha.
  2. Sistema identifica falha no envio (serviço de envio indisponível).
  3. Sistema interrompe o envio.
  4. Sistema informa ao usuário para tentar novamente mais tarde.

FE-E3 — Link/token expirado ou inválido

  1. Sistema identifica que o link/token utilizado é inválido ou que seu prazo de validade expirou.
  2. Sistema interrompe a redefinição.
  3. Sistema informa o usuário sobre a expiração e oferece a opção de solicitar um novo link.

FE-E4 — Nova senha não atende aos critérios de segurança

  1. Sistema identifica que a nova senha informada não atende aos critérios mínimos de segurança (RN17) ou que os campos de senha e confirmação não correspondem.
  2. Sistema interrompe a atualização da senha.
  3. Sistema informa o usuário sobre os critérios não atendidos e solicita nova tentativa.

Pós-condições

Sucesso

  • Nova senha definida pelo usuário.
  • Link/token de redefinição invalidado.
  • Alteração registrada no log de auditoria.

Falha

  • Nenhuma senha redefinida.
  • Senha anterior permanece válida.

Casos de Uso Relacionados

  • UC-05
  • UC-33
  • UC-36

UC-38: Excluir conta e dados pessoais

Objetivo: Permitir que o membro solicite a exclusão da própria conta e dos dados pessoais associados, respeitando os prazos previstos na LGPD e mediante aprovação do núcleo TOPS/Direx.

Atores: Usuário (todos os perfis), Núcleo TOPS, Direx

Pré-condições

  • Usuário está autenticado na plataforma. (UC-33)
  • Usuário possui perfil cadastrado, com consentimento LGPD previamente registrado. (UC-05) (RN16)

Fluxo Principal

  1. Usuário acessa a opção de exclusão de conta e dados pessoais no próprio perfil.
  2. Sistema exibe um aviso explicando as implicações da exclusão e solicita a confirmação do usuário. (FA-A1)
  3. Usuário confirma a solicitação de exclusão.
  4. Sistema registra a solicitação de exclusão, com data/hora, e a encaminha para aprovação do núcleo TOPS/Direx. (RN15)
  5. Sistema notifica o núcleo TOPS/Direx sobre a nova solicitação pendente.
  6. Usuário responsável (TOPS/Direx) analisa e aprova a solicitação. (FA-A2)
  7. Sistema exclui a conta e os dados pessoais do membro, respeitando os prazos estabelecidos pela LGPD. (RN15) (FE-E1)
  8. Sistema registra a exclusão no log de auditoria, contendo usuário solicitante, usuário aprovador, ação e data/hora.
  9. Sistema confirma ao núcleo TOPS/Direx a conclusão da exclusão.

Fluxos Alternativos

FA-A1 — Usuário desiste da exclusão

  1. Usuário opta por cancelar a solicitação após visualizar o aviso.
  2. Sistema encerra o processo sem registrar nenhuma solicitação.
  3. Sistema mantém a conta e os dados pessoais do membro inalterados.

FA-A2 — Solicitação reprovada pelo núcleo TOPS/Direx

  1. Usuário responsável (TOPS/Direx) reprova a solicitação de exclusão.
  2. Sistema registra a reprovação, com justificativa, no log de auditoria.
  3. Sistema notifica o membro solicitante sobre a reprovação da solicitação.
  4. Sistema mantém a conta e os dados pessoais do membro inalterados.

Fluxos de Exceção

FE-E1 — Falha na exclusão dos dados

  1. Sistema tenta excluir a conta e os dados pessoais do membro após a aprovação do núcleo TOPS/Direx.
  2. Sistema identifica falha técnica durante o processo de exclusão (ex.: indisponibilidade do banco de dados).
  3. Sistema interrompe a exclusão, mantém os dados do membro e registra a falha no log de auditoria para nova tentativa.

Pós-condições

Sucesso

  • Solicitação de exclusão aprovada.
  • Conta e dados pessoais do membro excluídos dentro dos prazos da LGPD.
  • Exclusão registrada no log de auditoria.

Falha

  • Conta e dados pessoais do membro permanecem inalterados.
  • Nenhuma exclusão realizada.

Casos de Uso Relacionados

  • UC-05
  • UC-33
