Casos de Uso

Especificação dos casos de uso referentes ao primeiro ciclo de desenvolvimento, contemplando os requisitos funcionais RF04, RF08, RF09, RF18, RF19 e RF22. O identificador e o nome de cada caso de uso correspondem diretamente ao requisito funcional de origem, e as regras de negócio (RN) aplicáveis estão indicadas nas etapas correspondentes de cada fluxo.

UC-04: Cadastrar perfil individual dos membros

Objetivo: Permitir o cadastro do perfil individual dos membros, registrando as informações pessoais e institucionais necessárias para a criação da conta e o acesso à plataforma.

Atores: Núcleo TOPS, Direx

Pré-condições

  • Ser da diretoria TOps ou DirEx.

Fluxo Principal

  1. Usuário acessa a tela de cadastro de perfil.
  2. Sistema exibe o formulário solicitando e-mail, senha, nome, CPF, data de nascimento, telefone, semestre atual ou semestre de entrada e diretoria/cargo.
  3. Usuário fornece as informações solicitadas.
  4. Sistema exibe e registra o consentimento explícito do usuário para o tratamento dos dados pessoais informados. (RN15) (UC-20) (FE-E1)
  5. Sistema valida os dados informados, verificando formato, unicidade do e-mail/CPF e preenchimento dos campos obrigatórios. (FE-E2) (FE-E3)
  6. Sistema processa o cadastro, criando a conta do usuário.
  7. Sistema confirma a criação do perfil.

Fluxos Alternativos

Nenhum

Fluxos de Exceção

FE-E1 — Usuário não consente com o tratamento de dados

  1. Sistema identifica que o usuário não manifestou consentimento ao termo de tratamento de dados apresentado. (RN15)
  2. Sistema interrompe o cadastro.
  3. Sistema informa que o consentimento é obrigatório para a conclusão do cadastro.

FE-E2 — Dados obrigatórios não informados

  1. Sistema identifica que um ou mais campos obrigatórios não foram preenchidos.
  2. Sistema interrompe o cadastro.
  3. Sistema informa o usuário sobre os campos pendentes.

FE-E3 — E-mail ou CPF já cadastrado

  1. Sistema identifica que o e-mail ou o CPF informado já está vinculado a outra conta.
  2. Sistema interrompe o cadastro.
  3. Sistema informa o usuário sobre a duplicidade e solicita a correção dos dados.

Pós-condições

Sucesso

  • Perfil do membro criado e vinculado à conta.
  • Consentimento LGPD registrado com data e hora.

Falha

  • Nenhum perfil criado.
  • Nenhum dado pessoal armazenado.

Casos de Uso Relacionados

  • UC-20
  • UC-23

UC-08: Exibir painel informativo

Objetivo: Exibir aos membros o painel informativo institucional, contendo Missão, Visão e Valores (MVV), Golden Circle, Planejamento Estratégico e os Objetivos do Ano.

Atores: Usuário (todos os perfis), Núcleo TOPS, Direx

Pré-condições

  • Usuário está autenticado na plataforma (UC-23).
  • Conteúdo do painel institucional foi previamente cadastrado.

Fluxo Principal

  1. Usuário acessa a área do painel informativo institucional.
  2. Sistema verifica a autenticação do usuário.
  3. Sistema busca o conteúdo vigente do painel (MVV, Golden Circle, Planejamento Estratégico, Objetivos do Ano). (FA-A1)(FE-E1)
  4. Sistema exibe o conteúdo do painel de forma visível e acessível a todos os membros da empresa. (RN08)
  5. Sistema disponibiliza o atalho de edição do conteúdo apenas para os perfis autorizados. (RN11) (FA-A2)

Fluxos Alternativos

FA-A1 — Painel institucional ainda não cadastrado

  1. Sistema identifica que não há conteúdo cadastrado para o painel informativo.
  2. Sistema interrompe a exibição do conteúdo.
  3. Sistema informa que o painel institucional ainda não foi configurado.

FA-A2 — Acesso de usuário autorizado à edição

  1. Sistema identifica que o usuário pertence ao núcleo TOPS ou à Direx. (RN11)
  2. Sistema disponibiliza o atalho para a edição do painel informativo. (UC-09)
  3. Fluxo retorna ao passo 4 do Fluxo Principal.

Fluxos de Exceção

FE-E1 — Erro ao carregar os dados do painel

  1. Sistema tenta carregar os dados do painel.
  2. Sistema identifica indisponibilidade do banco de dados.
  3. Sistema interrompe a operação.
  4. Sistema informa erro ao carregar os dados.

Pós-condições

Sucesso

  • Conteúdo do painel institucional exibido ao usuário.

Falha

  • Nenhum conteúdo exibido ao usuário.

Casos de Uso Relacionados

  • UC-09
  • UC-23

UC-09: Editar painel informativo

Objetivo: Permitir que o núcleo TOPS e a Direx editem o conteúdo do painel informativo institucional, garantindo que apenas informações oficiais aprovadas sejam exibidas aos membros.

Atores: Núcleo TOPS, Direx

Pré-condições

  • Usuário está autenticado e possui perfil TOPS ou Direx. (RN11)
  • Painel informativo institucional está previamente cadastrado (UC-08).

Fluxo Principal

  1. Usuário (TOPS/Direx) acessa a opção de edição do painel informativo.
  2. Sistema verifica se o perfil do usuário pertence ao núcleo TOPS ou à Direx. (RN11)
  3. Sistema exibe o conteúdo atual do painel para edição.
  4. Usuário edita as informações do MVV, Golden Circle, Planejamento Estratégico e/ou Objetivos do Ano.
  5. Sistema valida as informações editadas. (FE-E1)
  6. Sistema processa e salva as alterações realizadas.
  7. Sistema registra a operação no log de auditoria, contendo usuário, ação, data/hora e módulo afetado.
  8. Sistema confirma a atualização e disponibiliza o novo conteúdo a todos os membros. (RN08) (UC-08)

Fluxos Alternativos

Não se aplicam fluxos alternativos a este caso de uso.

Fluxos de Exceção

FE-E1 — Dados inválidos na edição

  1. Sistema identifica campos obrigatórios não preenchidos ou conteúdo em formato inválido.
  2. Sistema interrompe o salvamento das alterações.
  3. Sistema informa o usuário sobre os campos que precisam de correção.

Pós-condições

Sucesso

  • Conteúdo do painel institucional atualizado.
  • Alteração registrada no log de auditoria.

Falha

  • Nenhuma alteração salva.
  • Conteúdo do painel permanece inalterado.

Casos de Uso Relacionados

  • UC-08
  • UC-23

UC-19: Autenticar com múltiplo fator (MFA)

Objetivo: Exigir a validação de um segundo fator de autenticação, por meio de código enviado por e-mail, para conceder acesso à plataforma, reforçando a segurança do processo de login.

Atores: Usuário (todos os perfis: Direx, TOPS, Diretoria específica, Membro, Trainee)

Pré-condições

  • Usuário validou e-mail e senha, ou login via Google, com sucesso.

Fluxo Principal

  1. Sistema identifica o usuário e exige a segunda etapa de autenticação. (RN12)
  2. Sistema envia um código de verificação para o e-mail ou telefone cadastrado do usuário.
  3. Usuário informa o código recebido.
  4. Sistema valida o código informado, verificando a correspondência e o prazo de validade. (FE-E1)
  5. Sistema confirma a autenticação multifator.
  6. Sistema concede acesso à plataforma, dando prosseguimento ao processo de login. (UC-23)

Fluxos Alternativos

FA-A1 — Reenvio do código de verificação

  1. Usuário não recebe o código dentro do prazo esperado e solicita o reenvio.
  2. Sistema invalida o código anteriormente enviado e envia um novo código ao e-mail cadastrado.
  3. Fluxo retorna ao passo 3 do Fluxo Principal.

Fluxos de Exceção

FE-E1 — Código inválido ou expirado

  1. Sistema identifica que o código informado não corresponde ao código enviado ou que o prazo de validade expirou.
  2. Sistema interrompe a autenticação multifator.
  3. Sistema informa o usuário sobre a falha e oferece a opção de reenvio do código. (FA-A1)

Pós-condições

Sucesso

  • Autenticação multifator concluída com sucesso.
  • Acesso à plataforma liberado.

Falha

  • Autenticação multifator não concluída.
  • Acesso à plataforma permanece bloqueado.

Casos de Uso Relacionados

  • UC-23
  • UC-18

UC-20: Registrar consentimento LGPD

Objetivo: Apresentar e registrar o consentimento explícito do usuário para o tratamento dos seus dados pessoais no momento do cadastro do perfil, assegurando conformidade com a LGPD.

Atores: Usuário (novo membro em processo de cadastro)

Pré-condições

  • Usuário possui cadastro.

Fluxo Principal

  1. Sistema exibe ao usuário o termo de tratamento de dados pessoais (CPF, data de nascimento, foto, etc.) durante o primeiro login.
  2. Usuário realiza a leitura do termo apresentado.
  3. Usuário manifesta o consentimento explícito ao tratamento dos dados. (FE-E1)
  4. Sistema valida o registro do consentimento fornecido.
  5. Sistema grava o registro de aceite, incluindo data e hora, vinculado à conta do usuário. (RN15)
  6. Sistema prossegue com a conclusão do cadastro do perfil. (UC-04)

Fluxos Alternativos

Não se aplicam fluxos alternativos a este caso de uso.

Fluxos de Exceção

FE-E1 — Usuário não consente com o tratamento de dados

  1. Sistema identifica que o usuário não manifestou consentimento ao termo apresentado.
  2. Sistema interrompe o processo de cadastro do perfil.
  3. Sistema informa o usuário de que o consentimento é obrigatório para a conclusão do cadastro. (UC-04)

Pós-condições

Sucesso

  • Consentimento registrado com data e hora vinculados à conta do usuário.
  • Cadastro do perfil pode prosseguir.

Falha

  • Nenhum consentimento registrado.
  • Cadastro do perfil não é concluído.

Casos de Uso Relacionados

  • UC-04

UC-23: Realizar login

Objetivo: Permitir que o usuário acesse a plataforma mediante validação de suas credenciais, concedendo acesso às funcionalidades de acordo com o seu perfil de permissão (RBAC).

Atores: Usuário (Direx, TOPS, Diretoria específica, Membro, Trainee)

Pré-condições

  • Usuário possui conta cadastrada na plataforma (UC-04).
  • Usuário está na tela de login.

Fluxo Principal

  1. Usuário acessa a tela de login.
  2. Usuário opta por autenticar-se com e-mail corporativo e senha. (FA-A1)
  3. Usuário informa as credenciais solicitadas.
  4. Sistema valida as credenciais informadas, verificando a existência da conta e a correspondência da senha. (FE-E1)
  5. Sistema verifica se o usuário já possui autenticador de múltiplo fator cadastrado. (RN12) (FA-A2)
  6. Sistema exige a autenticação multifator do usuário. (RN12) (UC-19) (FE-E2)
  7. Sistema concede acesso às funcionalidades de acordo com o perfil de permissão (RBAC) do usuário (Direx, TOPS, Diretoria específica, Membro ou Trainee).
  8. Sistema registra o acesso realizado.

Fluxos Alternativos

FA-A1 — Autenticação via Google

  1. Usuário seleciona a opção de login com a conta Google.
  2. Sistema redireciona o usuário para o provedor de autenticação do Google.
  3. Sistema recebe a confirmação de identidade do provedor.
  4. Fluxo retorna ao passo 7 do Fluxo Principal.

FA-A2 — Primeiro acesso do usuário

  1. Sistema identifica que o usuário está realizando o primeiro login. (RN12)
  2. Sistema pede ao usuário o aceite dos Termos e Condições. (UC-20)
  3. Fluxo retorna ao passo 6 do Fluxo Principal.

Fluxos de Exceção

FE-E1 — Credenciais inválidas

  1. Sistema identifica que o e-mail ou a senha informados não correspondem a uma conta válida.
  2. Sistema interrompe o processo de autenticação.
  3. Sistema informa ao usuário que as credenciais são inválidas e solicita nova tentativa.

FE-E2 — Falha na verificação do MFA

  1. Sistema identifica que o código informado é inválido, expirado ou não foi informado dentro do prazo.
  2. Sistema interrompe a autenticação.
  3. Sistema informa o usuário sobre a falha, mantendo-o na etapa de verificação do MFA. (UC-19)

Pós-condições

Sucesso

  • Sessão autenticada iniciada para o usuário.
  • Acesso às funcionalidades correspondentes ao perfil liberado.

Falha

  • Nenhuma sessão é iniciada.
  • Usuário permanece na tela de login.

Casos de Uso Relacionados

  • UC-18
