Casos de Uso

Especificação dos casos de uso referentes ao primeiro ciclo de desenvolvimento, contemplando os requisitos funcionais RF05, RF06, RF07, RF14, RF15 e RF16, RF17, RF18, RF19, RF20, RF21, RF33, RF34. O identificador e o nome de cada caso de uso correspondem diretamente ao requisito funcional de origem, e as regras de negócio (RN) aplicáveis estão indicadas nas etapas correspondentes de cada fluxo.

UC-05: Cadastrar perfil individual dos membros

Objetivo: Permitir o cadastro do perfil individual dos membros, registrando as informações pessoais e institucionais necessárias para a criação da conta e o acesso à plataforma.

Atores: Núcleo TOPS, Direx

Pré-condições

  • Ser da diretoria TOps ou DirEx.

Fluxo Principal

  1. Usuário acessa a tela de cadastro de perfil.
  2. Sistema exibe o formulário solicitando e-mail, nome, CPF, data de nascimento, telefone, semestre atual ou semestre de entrada e diretoria/cargo.
  3. Usuário fornece as informações solicitadas.
  4. Sistema exibe e registra o consentimento explícito do usuário para o tratamento dos dados pessoais informados. (RN16) (FE-E1)
  5. Sistema valida os dados informados, verificando formato, unicidade do e-mail/CPF e preenchimento dos campos obrigatórios. (FE-E2) (FE-E3)
  6. Sistema processa o cadastro, criando a conta do usuário.
  7. Sistema confirma a criação do perfil.

Fluxos Alternativos

Nenhum

Fluxos de Exceção

FE-E1 — Usuário não consente com o tratamento de dados

  1. Sistema identifica que o usuário não manifestou consentimento ao termo de tratamento de dados apresentado. (RN16)
  2. Sistema interrompe o cadastro.
  3. Sistema informa que o consentimento é obrigatório para a conclusão do cadastro.

FE-E2 — Dados obrigatórios não informados

  1. Sistema identifica que um ou mais campos obrigatórios não foram preenchidos.
  2. Sistema interrompe o cadastro.
  3. Sistema informa o usuário sobre os campos pendentes.

FE-E3 — E-mail ou CPF já cadastrado

  1. Sistema identifica que o e-mail ou o CPF informado já está vinculado a outra conta.
  2. Sistema interrompe o cadastro.
  3. Sistema informa o usuário sobre a duplicidade e solicita a correção dos dados.

Pós-condições

Sucesso

  • Perfil do membro criado e vinculado à conta.
  • Consentimento LGPD registrado com data e hora.

Falha

  • Nenhum perfil criado.
  • Nenhum dado pessoal armazenado.

Casos de Uso Relacionados

  • UC-06
  • UC-33

UC-06: Gerar e enviar senha temporária no cadastro do membro

Objetivo: Gerar automaticamente uma senha temporária aleatória, com no exatamente 15 caracteres, e enviá-la por e-mail ao membro recém-cadastrado, para uso no primeiro acesso à plataforma.

Atores: Sistema (acionado automaticamente ao final do cadastro), Núcleo TOPS, Direx

Pré-condições

  • Cadastro do perfil do membro foi concluído com sucesso (UC-05).
  • Consentimento LGPD registrado.

Fluxo Principal

  1. Sistema identifica a conclusão do cadastro do perfil do membro. (UC-05)
  2. Sistema gera automaticamente uma senha temporária aleatória, com exatamente 15 caracteres.
  3. Sistema associa a senha temporária gerada à conta do membro.
  4. Sistema envia a senha temporária para o e-mail cadastrado do membro. (FE-E1)
  5. Sistema registra o envio da senha temporária, incluindo data e hora.
  6. Sistema confirma a conclusão do processo de geração e envio da senha temporária.

Fluxos Alternativos

FA-A1 — Reenvio da senha temporária

  1. Usuário responsável (TOPS/Direx) solicita o reenvio da senha temporária ao membro.
  2. Sistema invalida a senha temporária anteriormente gerada.
  3. Sistema gera uma nova senha temporária aleatória, com no exatamente 15 caracteres.
  4. Fluxo retorna ao passo 3 do Fluxo Principal.

Fluxos de Exceção

FE-E1 — Falha no envio do e-mail

  1. Sistema tenta enviar o e-mail com a senha temporária.
  2. Sistema identifica falha no envio (e-mail inválido ou serviço de envio indisponível).
  3. Sistema interrompe o envio.
  4. Sistema informa ao Núcleo TOPS/Direx responsável pelo cadastro sobre a falha, oferecendo a opção de reenvio. (FA-A1)

Pós-condições

Sucesso

  • Senha temporária gerada e enviada ao e-mail do membro.
  • Registro do envio armazenado.

Falha

  • Nenhuma senha temporária enviada.
  • Membro não consegue realizar o primeiro acesso à plataforma.

Casos de Uso Relacionados

  • UC-05
  • UC-07
  • UC-33

UC-07: Exigir troca de senha no primeiro login

Objetivo: Obrigar o membro a definir uma nova senha ao autenticar-se pela primeira vez com a senha temporária gerada, antes de liberar o acesso às demais funcionalidades da plataforma.

Atores: Usuário (todos os perfis, em primeiro acesso)

Pré-condições

  • Membro possui senha temporária gerada e enviada por e-mail (UC-06).
  • Usuário realizou login com e-mail e senha temporária com sucesso (UC-33).

Fluxo Principal

  1. Sistema identifica que o usuário está autenticando-se com a senha temporária gerada no cadastro. (UC-06)
  2. Sistema interrompe o acesso às demais funcionalidades da plataforma.
  3. Sistema exibe o formulário de definição de nova senha.
  4. Usuário informa a nova senha e a confirmação da nova senha.
  5. Sistema valida a nova senha informada, verificando os critérios de segurança e a correspondência entre os campos. (FE-E1)(FE-E2)
  6. Sistema processa a atualização, substituindo a senha temporária pela nova senha definida.
  7. Sistema invalida a senha temporária utilizada.
  8. Sistema registra a operação no log de auditoria, contendo usuário, ação e data/hora.
  9. Sistema confirma a troca de senha e libera o acesso às funcionalidades correspondentes ao perfil do usuário. (UC-33)

Fluxos Alternativos

Não se aplicam fluxos alternativos a este caso de uso.

Fluxos de Exceção

FE-E1 — Nova senha não atende aos critérios de segurança

  1. Sistema identifica que a senha informada não atende aos critérios mínimos de segurança definidos.
  2. Sistema interrompe a atualização da senha.
  3. Sistema informa o usuário sobre os critérios não atendidos e solicita nova tentativa.

FE-E2 — Confirmação de senha não corresponde

  1. Sistema identifica que os campos de nova senha e confirmação de senha não correspondem.
  2. Sistema interrompe a atualização da senha.
  3. Sistema informa o usuário sobre a divergência e solicita nova tentativa.

Pós-condições

Sucesso

  • Nova senha definida pelo membro.
  • Senha temporária invalidada.
  • Acesso às funcionalidades da plataforma liberado, conforme o perfil do usuário.

Falha

  • Nenhuma senha definida.
  • Senha temporária permanece válida.
  • Acesso às demais funcionalidades da plataforma permanece bloqueado.

Casos de Uso Relacionados

  • UC-06
  • UC-33

UC-14: Consultar MVV e Golden Circle

Objetivo: Exibir aos membros o painel institucional com Missão, Visão, Valores (MVV) e Golden Circle.

Atores: Usuário (todos os perfis)

Pré-condições

  • Usuário está autenticado na plataforma (UC-33).
  • Conteúdo de MVV e Golden Circle foi previamente cadastrado.

Fluxo Principal

  1. Usuário acessa a área do painel institucional referente a MVV e Golden Circle.
  2. Sistema verifica a autenticação do usuário.
  3. Sistema busca o conteúdo vigente de MVV e Golden Circle. (FA-A1)(FE-E1)
  4. Sistema exibe o conteúdo de forma visível e acessível a todos os membros da empresa. (RN08)
  5. Sistema disponibiliza o atalho de edição do conteúdo apenas para os perfis autorizados. (RN11) (FA-A2)

Fluxos Alternativos

FA-A1 — MVV e Golden Circle ainda não cadastrados

  1. Sistema identifica que não há conteúdo cadastrado para MVV e Golden Circle.
  2. Sistema interrompe a exibição do conteúdo.
  3. Sistema informa que o conteúdo de MVV e Golden Circle ainda não foi configurado.

FA-A2 — Acesso de usuário autorizado à edição

  1. Sistema identifica que o usuário pertence ao núcleo TOPS ou à Direx. (RN11)
  2. Sistema disponibiliza o atalho para a edição de MVV e Golden Circle. (UC-15)
  3. Fluxo retorna ao passo 4 do Fluxo Principal.

Fluxos de Exceção

FE-E1 — Erro ao carregar os dados de MVV e Golden Circle

  1. Sistema tenta carregar os dados de MVV e Golden Circle.
  2. Sistema identifica indisponibilidade do banco de dados.
  3. Sistema interrompe a operação.
  4. Sistema informa erro ao carregar os dados.

Pós-condições

Sucesso

  • Conteúdo de MVV e Golden Circle exibido ao usuário.

Falha

  • Nenhum conteúdo exibido ao usuário.

Casos de Uso Relacionados

  • UC-15
  • UC-33

UC-15: Editar MVV e Golden Circle

Objetivo: Permitir que o núcleo TOPS e a Direx editem o conteúdo de MVV e Golden Circle exibido no painel institucional, garantindo que apenas informações oficiais aprovadas sejam exibidas aos membros.

Atores: Núcleo TOPS, Direx

Pré-condições

  • Usuário está autenticado e possui perfil TOPS ou Direx. (RN11)
  • Conteúdo de MVV e Golden Circle está previamente cadastrado (UC-14).

Fluxo Principal

  1. Usuário (TOPS/Direx) acessa a opção de edição de MVV e Golden Circle.
  2. Sistema verifica se o perfil do usuário pertence ao núcleo TOPS ou à Direx. (RN11)
  3. Sistema exibe o conteúdo atual de MVV e Golden Circle para edição.
  4. Usuário edita as informações de Missão, Visão, Valores e/ou Golden Circle.
  5. Sistema valida as informações editadas. (FE-E1)
  6. Sistema processa e salva as alterações realizadas.
  7. Sistema registra a operação no log de auditoria, contendo usuário, ação, data/hora e módulo afetado.
  8. Sistema confirma a atualização e disponibiliza o novo conteúdo a todos os membros. (RN08) (UC-14)

Fluxos Alternativos

Não se aplicam fluxos alternativos a este caso de uso.

Fluxos de Exceção

FE-E1 — Dados inválidos na edição

  1. Sistema identifica campos obrigatórios não preenchidos ou conteúdo em formato inválido.
  2. Sistema interrompe o salvamento das alterações.
  3. Sistema informa o usuário sobre os campos que precisam de correção.

Pós-condições

Sucesso

  • Conteúdo de MVV e Golden Circle atualizado.
  • Alteração registrada no log de auditoria.

Falha

  • Nenhuma alteração salva.
  • Conteúdo de MVV e Golden Circle permanece inalterado.

Casos de Uso Relacionados

  • UC-14
  • UC-33

UC-18: Cadastrar plano de ação

Objetivo: Permitir o cadastro de um plano de ação vinculado a um objetivo estratégico do ano, definindo as ações necessárias para alcançá-lo.

Atores: Núcleo TOPS, Direx

Pré-condições

  • Usuário está autenticado e possui perfil TOPS ou Direx. (RN11)
  • Objetivo estratégico do ano está previamente cadastrado (UC-16)(UC-17).

Fluxo Principal

  1. Usuário acessa a tela de cadastro de plano de ação.
  2. Sistema exibe a lista de objetivos estratégicos do ano cadastrados para seleção.
  3. Usuário seleciona o objetivo estratégico ao qual o plano de ação será vinculado.
  4. Sistema exibe o formulário solicitando as ações necessárias, prazo e demais informações do plano de ação.
  5. Usuário fornece as informações solicitadas.
  6. Sistema valida os dados informados, verificando o preenchimento dos campos obrigatórios. (FE-E1)
  7. Sistema processa o cadastro, vinculando o plano de ação ao objetivo estratégico selecionado.
  8. Sistema registra a operação no log de auditoria, contendo usuário, ação, data/hora e módulo afetado.
  9. Sistema confirma a criação do plano de ação.

Fluxos Alternativos

Não se aplicam fluxos alternativos a este caso de uso.

Fluxos de Exceção

FE-E1 — Dados obrigatórios não informados

  1. Sistema identifica que um ou mais campos obrigatórios não foram preenchidos.
  2. Sistema interrompe o cadastro.
  3. Sistema informa o usuário sobre os campos pendentes.

Pós-condições

Sucesso

  • Plano de ação criado e vinculado ao objetivo estratégico correspondente.
  • Cadastro registrado no log de auditoria.

Falha

  • Nenhum plano de ação criado.

Casos de Uso Relacionados

  • UC-16
  • UC-17
  • UC-19

UC-19: Vincular membros a plano de ação

Objetivo: Permitir vincular um ou mais membros a um plano de ação, associando-os à execução do objetivo estratégico correspondente e refletindo esse vínculo no perfil do membro.

Atores: Núcleo TOPS, Direx

Pré-condições

  • Usuário está autenticado e possui perfil TOPS ou Direx. (RN11)
  • Plano de ação está previamente cadastrado (UC-18).
  • Membro(s) a serem vinculados possuem perfil cadastrado na plataforma (UC-05).

Fluxo Principal

  1. Usuário acessa a tela de vinculação de membros ao plano de ação.
  2. Sistema exibe a lista de planos de ação cadastrados para seleção.
  3. Usuário seleciona o plano de ação desejado.
  4. Sistema exibe a lista de membros cadastrados para seleção. (FE-E2)
  5. Usuário seleciona um ou mais membros a serem vinculados. (FE-E1)
  6. Sistema valida a seleção realizada.
  7. Sistema processa o vínculo, associando o(s) membro(s) ao plano de ação e ao objetivo estratégico correspondente.
  8. Sistema atualiza o perfil de cada membro vinculado, refletindo a associação ao plano de ação.
  9. Sistema registra a operação no log de auditoria, contendo usuário, ação, data/hora e módulo afetado.
  10. Sistema confirma o vínculo realizado.

Fluxos Alternativos

Não se aplicam fluxos alternativos a este caso de uso.

Fluxos de Exceção

FE-E1 — Membro já vinculado ao plano de ação

  1. Sistema identifica que o membro selecionado já está vinculado ao plano de ação.
  2. Sistema interrompe a vinculação para o membro em questão.
  3. Sistema informa o usuário sobre a duplicidade do vínculo.

FE-E2 — Nenhum membro cadastrado disponível

  1. Sistema identifica que não há membros cadastrados na plataforma. (UC-05)
  2. Sistema interrompe a operação.
  3. Sistema informa que não há membros disponíveis para vinculação.

Pós-condições

Sucesso

  • Membro(s) vinculado(s) ao plano de ação e ao objetivo estratégico correspondente.
  • Vínculo refletido no perfil de cada membro.
  • Vinculação registrada no log de auditoria.

Falha

  • Nenhum vínculo realizado.
  • Perfil do(s) membro(s) permanece inalterado.

Casos de Uso Relacionados

  • UC-05
  • UC-18

UC-20: Editar status do objetivo/plano de ação

Objetivo: Permitir a atualização do status do objetivo estratégico e/ou de seu plano de ação (ex: não iniciado, em andamento, concluído, atrasado).

Atores: Núcleo TOPS, Direx, Membro (vinculado ao plano de ação)

Pré-condições

  • Usuário está autenticado. (UC-33)
  • Usuário possui perfil TOPS/Direx ou está vinculado ao plano de ação como membro executor. (RN11) (UC-19)
  • Objetivo estratégico e/ou plano de ação estão previamente cadastrados (UC-16)(UC-17)(UC-18).

Fluxo Principal

  1. Usuário acessa a tela de acompanhamento do objetivo estratégico e/ou do plano de ação.
  2. Sistema verifica se o usuário pertence ao núcleo TOPS/Direx ou está vinculado ao plano de ação. (RN11) (FE-E2)
  3. Sistema exibe o status atual do objetivo estratégico e/ou do plano de ação.
  4. Usuário seleciona o novo status a ser atribuído (não iniciado, em andamento, concluído ou atrasado).
  5. Sistema valida a alteração informada. (FE-E1)
  6. Sistema processa e salva a atualização de status.
  7. Sistema registra a operação no log de auditoria, contendo usuário, ação, data/hora e módulo afetado.
  8. Sistema confirma a atualização e disponibiliza o novo status. (UC-21)

Fluxos Alternativos

Não se aplicam fluxos alternativos a este caso de uso.

Fluxos de Exceção

FE-E1 — Status inválido

  1. Sistema identifica que o status selecionado não corresponde a uma opção válida.
  2. Sistema interrompe o salvamento da alteração.
  3. Sistema informa o usuário sobre a necessidade de selecionar um status válido.

FE-E2 — Usuário não autorizado

  1. Sistema identifica que o usuário não pertence ao núcleo TOPS/Direx e não está vinculado ao plano de ação. (RN11)
  2. Sistema interrompe o acesso à edição de status.
  3. Sistema informa o usuário que ele não possui permissão para realizar a alteração.

Pós-condições

Sucesso

  • Status do objetivo estratégico e/ou do plano de ação atualizado.
  • Alteração registrada no log de auditoria.

Falha

  • Nenhuma alteração salva.
  • Status do objetivo estratégico e/ou do plano de ação permanece inalterado.

Casos de Uso Relacionados

  • UC-18
  • UC-19
  • UC-21

UC-21: Consultar plano de ação

Objetivo: Exibir o status atual de cada objetivo estratégico e de seu(s) plano(s) de ação associado(s), permitindo acompanhar o progresso ao longo do ano.

Atores: Usuário (todos os perfis)

Pré-condições

  • Usuário está autenticado na plataforma (UC-33).
  • Objetivo estratégico e/ou plano de ação foram previamente cadastrados (UC-16)(UC-18).

Fluxo Principal

  1. Usuário acessa a área de acompanhamento dos objetivos estratégicos e planos de ação.
  2. Sistema verifica a autenticação do usuário.
  3. Sistema busca o status vigente de cada objetivo estratégico e de seu(s) plano(s) de ação associado(s). (FA-A1)(FE-E1)
  4. Sistema exibe o status de forma visível e acessível a todos os membros da empresa. (RN08)
  5. Sistema disponibiliza o atalho de edição de status apenas para os perfis autorizados ou membros vinculados ao plano de ação. (RN11) (FA-A2)

Fluxos Alternativos

FA-A1 — Nenhum objetivo/plano de ação cadastrado

  1. Sistema identifica que não há objetivo estratégico e/ou plano de ação cadastrado.
  2. Sistema interrompe a exibição do conteúdo.
  3. Sistema informa que ainda não há objetivos e/ou planos de ação cadastrados.

FA-A2 — Acesso de usuário autorizado à edição de status

  1. Sistema identifica que o usuário pertence ao núcleo TOPS/Direx ou está vinculado ao plano de ação. (RN11) (UC-19)
  2. Sistema disponibiliza o atalho para a edição do status. (UC-20)
  3. Fluxo retorna ao passo 4 do Fluxo Principal.

Fluxos de Exceção

FE-E1 — Erro ao carregar os dados de status

  1. Sistema tenta carregar os dados de status dos objetivos estratégicos e planos de ação.
  2. Sistema identifica indisponibilidade do banco de dados.
  3. Sistema interrompe a operação.
  4. Sistema informa erro ao carregar os dados.

Pós-condições

Sucesso

  • Status dos objetivos estratégicos e planos de ação exibido ao usuário.

Falha

  • Nenhum status exibido ao usuário.

Casos de Uso Relacionados

  • UC-19
  • UC-20

UC-33: Realizar login

Objetivo: Permitir que o usuário acesse a plataforma mediante validação de suas credenciais, concedendo acesso às funcionalidades de acordo com o seu perfil de permissão (RBAC).

Atores: Usuário (Direx, TOPS, Diretoria específica, Membro, Trainee)

Pré-condições

  • Usuário possui conta cadastrada na plataforma (UC-05).
  • Usuário está na tela de login.

Fluxo Principal

  1. Usuário acessa a tela de login.
  2. Usuário opta por autenticar-se com e-mail corporativo e senha. (FA-A1)
  3. Usuário informa as credenciais solicitadas.
  4. Sistema valida as credenciais informadas, verificando a existência da conta e a correspondência da senha. (FE-E1)
  5. Sistema verifica se o usuário já possui autenticador de múltiplo fator cadastrado. (RN12) (FA-A2)
  6. Sistema exige a autenticação multifator do usuário. (RN12) (UC-34) (FE-E2)
  7. Sistema concede acesso às funcionalidades de acordo com o perfil de permissão (RBAC) do usuário (Direx, TOPS, Diretoria específica, Membro ou Trainee).
  8. Sistema registra o acesso realizado.

Fluxos Alternativos

FA-A1 — Autenticação via Google

  1. Usuário seleciona a opção de login com a conta Google.
  2. Sistema redireciona o usuário para o provedor de autenticação do Google.
  3. Sistema recebe a confirmação de identidade do provedor.
  4. Fluxo retorna ao passo 7 do Fluxo Principal.

FA-A2 — Primeiro acesso do usuário

  1. Sistema identifica que o usuário está realizando o primeiro login. (RN12)
  2. Sistema pede ao usuário o aceite dos Termos e Condições. (RN16)
  3. Fluxo retorna ao passo 6 do Fluxo Principal.

Fluxos de Exceção

FE-E1 — Credenciais inválidas

  1. Sistema identifica que o e-mail ou a senha informados não correspondem a uma conta válida.
  2. Sistema interrompe o processo de autenticação.
  3. Sistema informa ao usuário que as credenciais são inválidas e solicita nova tentativa.

FE-E2 — Falha na verificação do MFA

  1. Sistema identifica que o código informado é inválido, expirado ou não foi informado dentro do prazo.
  2. Sistema interrompe a autenticação.
  3. Sistema informa o usuário sobre a falha, mantendo-o na etapa de verificação do MFA. (UC-34)

Pós-condições

Sucesso

  • Sessão autenticada iniciada para o usuário.
  • Acesso às funcionalidades correspondentes ao perfil liberado.

Falha

  • Nenhuma sessão é iniciada.
  • Usuário permanece na tela de login.

Casos de Uso Relacionados

  • UC-05
  • UC-34

UC-34: Autenticar com múltiplo fator (MFA)

Objetivo: Exigir a validação de um segundo fator de autenticação, por meio de código enviado por e-mail, para conceder acesso à plataforma, reforçando a segurança do processo de login.

Atores: Usuário (todos os perfis: Direx, TOPS, Diretoria específica, Membro, Trainee)

Pré-condições

  • Usuário validou e-mail e senha, ou login via Google, com sucesso.

Fluxo Principal

  1. Sistema identifica o usuário e exige a segunda etapa de autenticação. (RN12)
  2. Sistema envia um código de verificação para o e-mail ou telefone cadastrado do usuário.
  3. Usuário informa o código recebido.
  4. Sistema valida o código informado, verificando a correspondência e o prazo de validade. (FE-E1)
  5. Sistema confirma a autenticação multifator.
  6. Sistema concede acesso à plataforma, dando prosseguimento ao processo de login. (UC-33)

Fluxos Alternativos

FA-A1 — Reenvio do código de verificação

  1. Usuário não recebe o código dentro do prazo esperado e solicita o reenvio.
  2. Sistema invalida o código anteriormente enviado e envia um novo código ao e-mail cadastrado.
  3. Fluxo retorna ao passo 3 do Fluxo Principal.

Fluxos de Exceção

FE-E1 — Código inválido ou expirado

  1. Sistema identifica que o código informado não corresponde ao código enviado ou que o prazo de validade expirou.
  2. Sistema interrompe a autenticação multifator.
  3. Sistema informa o usuário sobre a falha e oferece a opção de reenvio do código. (FA-A1)

Pós-condições

Sucesso

  • Autenticação multifator concluída com sucesso.
  • Acesso à plataforma liberado.

Falha

  • Autenticação multifator não concluída.
  • Acesso à plataforma permanece bloqueado.

Casos de Uso Relacionados

  • UC-33
